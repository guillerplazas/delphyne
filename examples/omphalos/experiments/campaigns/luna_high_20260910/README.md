# Luna high-effort diagnostic

The user clarified that the intended effort increase was for Luna, not Terra.
This new campaign implements that request. It does not relabel the completed
Terra run or use previous unused budget as authorization.

Six saved trainX states, seed 0, in the original panel order; gpt-5.6-luna
high versus archived Luna medium fixed-demo applicability phases. The five
fixed demos, tools, Responses API, output limit 32768, temperature unset,
verifier limits and four-request maximum are unchanged. Local dollar cap
$0.10, new campaign ceiling $0.60, one worker, zero retries/teacher budget.
Full X budgets remain $0.10. No full problems, validation or automatic
additional effort levels are authorized by this registration.

Primary endpoint: correct applicability. Practical signal: at least one
additional correct decision and no lost previously correct state versus
medium. Report all-cell cost and cost/correct separately. One paired
family-clustered two-sided comparison, p<0.10, descriptive 90% intervals;
practical and statistical rules are separate. Six inspected families at one
seed with historical controls are exploratory and cannot establish general
coverage, equivalence, end-to-end savings or ACE value. Failures stay in the
denominator; missing/censored cells prohibit ranking. Unknown is not refutation.

The Luna medium controls are only their applicability phase; ordinary
continuation charges are excluded from this phase comparison. High stops
after applicability, as the previous Terra diagnostic did. The shared
ChangeConfig's stage="terra" flag selects that existing stopping branch;
the actual model remains Luna. No strategy, policy, prompt, tool or budgeting
mechanism was changed. Configuration checks verify the model/effort/limits.
Actual first requests are audited against the medium requests after execution.

The module docstring, schedule, source dependencies and archived controls
were frozen before launch. Both harnesses use the same module with the
supervised launcher/tmux and runtime/campaign_budget.py. launch.json records
the command. Earlier paid campaigns and staged work remain unchanged.

The deployment target remains at least 15% lower full-problem total cost and
cost per qualified solve with no observed coverage loss. Applicability
correctness alone does not qualify as useful downstream progress or a solve.
